# Bug Hunt — 2026-07-12

Exhaustive multi-agent bug hunt over `meme_intelligence/` (~9,450 lines, 37
source files), followed by manual adversarial verification of every candidate
against the real code.

**Result: 42 of 43 findings fixed (the 43rd is correct as-is); all tests green
(302 pass, up from 274).**

- **Round 1** — 17 correctness / 24-7-resilience bugs (loop-killers, alert
  delivery, blacklisting, parsing). Detailed below.
- **Round 2** — the 25 remaining scoring-shape / tuning / lower-priority
  findings, drafted by a second multi-agent workflow (one analyst per file +
  a consistency reviewer), then applied and tested. Summarized at the bottom.
- **Left by design** — #28 (liquidity feeds both market- and execution-risk):
  liquidity genuinely drives both volatility and exit risk; removing it would
  make the scanner *less* conservative. Correctly unchanged.

## How this run went

A multi-agent workflow fanned out 18 per-module finders + 6 cross-cutting lens
sweeps (concurrency, financial-safety, error-handling, data-validation,
API-parsing, logic/math). The finders surfaced **43 candidate findings** before
the run hit the monthly Anthropic spend limit, which killed the automated
adversarial-verification stage (161 of 178 agents errored on the limit).

Rather than report the misleading "0 confirmed" that the truncated run
produced, the 43 candidates were recovered from the workflow journal and
**verified by hand against the source**. 17 were confirmed as genuine
correctness/resilience bugs and fixed with regression tests; the rest are
scoring-shape/tuning judgments documented below for your decision (changing
them alters tuned alert behavior, which is your call per the standing rule).

## Fixed — correctness & 24/7 resilience (17)

### Loop-killers (would crash the always-on scanner)

| # | File | Bug | Fix |
|---|------|-----|-----|
| 1 | `core/models.py` `classify` | A weighted average of maxed-out categories can land at `100.0000000001` (float rounding, e.g. `100.0*0.15/0.15`); the strict range check raised a `ValueError`, which is **not** a `MemeIntelError`, so it escaped the cycle handler and killed the loop. | Tolerate float epsilon, clamp into range; still reject genuinely out-of-range input. |
| 10 | `core/models.py` / `scoring_engine.py` | `compute_weighted_score` / `_weighted` returned the raw `weighted_sum/available`, unclamped, breaking the documented 0–100 contract. | Clamp both to `[0, 100]`. |
| 4 | `collectors/market_data.py` | `_from_ms_timestamp` let `NaN`/`Inf`/out-of-range values through (`float("nan")` succeeds, `nan <= 0` is False), then `datetime.fromtimestamp` raised `ValueError`/`OverflowError`/`OSError` — uncaught by `_parse_pairs`, aborting the batch and escaping as a non-`CollectorError`. | Harden `_to_float` to reject non-finite; guard the timestamp conversion. |
| 26 | `workflow/controller.py` | The cycle loop caught only `MemeIntelError`, so a `sqlite3.OperationalError`, sink failure, or stray exception killed the 24/7 loop — violating the module's own "one failing cycle never kills the scanner" contract. | Catch `Exception` (backoff + continue); `KeyboardInterrupt`/`CancelledError` still propagate for graceful shutdown. |
| 24 | `scanners/discovery.py` | `scan_new_pools` had no per-network isolation: one network's collector error discarded every other network's freshly fetched pools. | Isolate per network; re-raise only on total failure so a real outage still backs off. |

### Alert delivery correctness

| # | File | Bug | Fix |
|---|------|-----|-----|
| 6 | `alerts/notification_engine.py` | `dispatch` recorded the cooldown timestamp **before** sending; a failed send permanently suppressed that (possibly CRITICAL) alert for the whole cooldown window. | Record cooldown only after ≥1 successful delivery. |
| 22 | `alerts/notification_engine.py` | No per-sink error isolation: one sink raising aborted delivery of every remaining event in the batch (and could crash the loop). | Wrap each sink send in try/except; a failing sink no longer sinks the batch. |
| 23 | `alerts/notification_engine.py` | `_last_sent` cooldown map grew without bound over a 24/7 run — a slow leak on the memory-constrained box. | Prune expired entries (behavior-neutral) once the map is large. |

### Candidate handling & watchlist

| # | File | Bug | Fix |
|---|------|-----|-----|
| 9 | `workflow/controller.py` | A token was added to `_seen` **before** analysis succeeded, so a transient security-data miss (e.g. GoPlus not yet indexing a brand-new token) permanently blacklisted it for the session. | Mark `_seen` only after a successful analysis. |
| 25 | `workflow/controller.py` | `candidates[:top_candidates]` was sliced **before** the seen-set filter, so already-seen tokens consumed the top-N slots and starved fresh candidates ranked just below. | Filter unseen first, then slice. |
| 8 | `workflow/controller.py` | `_recheck_watchlist` archived a tracked token whenever `get_best_pair` returned `None` — but that return conflates "no pairs exist" with "all providers failed," so a transient outage permanently archived healthy tokens. | Use `get_token_pairs` + catch `CollectorError`/`AllProvidersFailedError` → skip (retry next recheck); archive only on a genuinely empty pair list. Mirrors `watchlist_review.py`. |

### Data parsing / security accuracy

| # | File | Bug | Fix |
|---|------|-----|-----|
| 2 | `collectors/security_data.py` | Solana `transfer_fee_upgradable` is a nested `{"status": …}` object (like every other Solana authority) but was parsed with `_flag`, which stringifies the dict → **always False**. A modifiable transfer fee was never detected on the primary chain. | Parse via `authority_status`, consistent with the other Solana authorities. |
| 13 | `collectors/security_data.py` | `_is_burn_address` used a bare `"dead" in address` substring test, so any holder/LP address merely containing "dead" was dropped from concentration analysis (understating concentration) or counted as LP-locked (overstating safety). | Exact-match a set of known EVM/Solana burn addresses. |
| 19 | `collectors/market_data.py` | GeckoTerminal base-token id `"<network>_<address>"` was split on the **first** underscore, corrupting chain + address for networks whose id contains one (`polygon_pos`, `arbitrum_nova`). | Split on the **last** underscore (`rpartition`) — token addresses never contain `_`. |
| 33 | `collectors/market_service.py` | When both liquidity figures were exactly `0.0`, the `low > 0` guard fell through to "sources disagree," wrongly flagging two agreeing sources. | Treat identical figures (including both-zero) as agreement. |

### Configuration robustness

| # | File | Bug | Fix |
|---|------|-----|-----|
| 27 | `config/settings.py` | `_convert` accepted `nan`/`inf` from env; a NaN weight silently bypassed the weight-sum guard (`abs(nan-1.0) > tol` is False) and poisoned every composite score. | Reject non-finite floats with a `ConfigurationError`. |
| 39 | `config/settings.py` | Sub-weight classes validated only that weights sum to 1.0, not that each is in `[0,1]`, so a negative weight compensated elsewhere passed and inverted a component. | Range-check every weight inside `_check_weight_sum`. |

## Round 2 — scoring-shape / tuning / lower-priority fixes (25)

Drafted by a second workflow (one analyst per file + a consistency reviewer),
then applied and tested. Most *tighten* correctness (suspect signals score low,
new coins aren't falsely flagged), so they make alerts quieter, not louder.

**Momentum (`momentum_analyzer.py`)** — **#3** suspect volume now folds a low
signal in so a suspect-volume-only lens scores ~0 not 75; **#15** an unsupported
1h spike scores low not 85; **#16** a consistent downtrend gets a low signal (20)
not the neutral "mixed" 60.

**On-chain (`onchain_analyzer.py`)** — **#14** wash-trade denominator uses
`max(buyers, sellers)` (a conservative unique-trader bound) instead of the sum,
so churn is no longer hidden; **#30** holder-growth is anchored symmetrically so
a token that grew never scores below one that lost holders.

**Risk (`risk_analyzer.py`)** — **#11** a confirmed honeypot/rug now floors the
risk *category* to EXTREME (was possibly MODERATE).

**Sub-score core (`common.py`)** — **#12** a category holding a DESTRUCTIVE
finding now scores 0, not a misleading 100.

**Community (`community_analyzer.py`)** — **#18 / #31 / #32** a lone clean risk
gate no longer invents a perfect 100; it scores nothing and reports "no data".

**Wallet intel (`wallet_intelligence.py`)** — **#5** same-size-trade detection
requires >=5 trades; **#35** dominant-buyer detection requires >=2 buyers — so a
thin/fresh launch with one legitimate buyer is no longer flagged ARTIFICIAL
(honors "a new coin is never punished just for being new").

**Trade planner (`trade_planner.py`)** — **#7** only genuine per-token evidence
lifts the SPECULATIVE cap; the global market-regime signal no longer counts as
per-token confirmation. *Caveat: this re-bases the tuned `min_confirmation_coverage`
(0.50) against per-token-only coverage — a deliberate conviction-tightening. If
you'd rather keep the old sizing, revert this one or give it its own threshold.*

**Token (`token_analyzer.py`)** — **#17** market cap <= 0 is treated as missing
and falls back to FDV, else raises `InsufficientDataError` (no more "Good" on a
zero-cap token).

**Collectors** — **#20** (`market_service.py`) cross-check skips a byte-identical
snapshot so a provider can't self-confirm when the primary is cooling down
(*partial fix — a full one needs to plumb the pair's source provider through*);
**#21** (`wallet_data.py`) holder balances fall back to raw `amount`+`decimals`
when the deprecated `uiAmount` is null; **#34** partial results survive a
mid-gather provider failure; **#29** (`security_data.py`) EVM `tax_modifiable`
no longer duplicates `slippage_modifiable` (one signal, one deduction).

**Scanner (`discovery.py`)** — **#36** filter runs before dedupe so a deep-but-
stale pool can't shadow a fresh valid one.

**Daily routine (`daily_routine.py`)** — **#37** security changes keep worst-
first order (CRITICAL stays in the rendered top-5); **#38** the daily watchlist-
review path now runs contract-change monitoring like the discovery path.
*(These two share a new `_monitor_security_changes` helper; #38 adds a genuinely
new alert source — deterioration on already-tracked tokens — the only round-2
change that can produce more alerts, and only on known->known worsening.)*

**Core** — **#40** (`provider_pool.py`) provider state keyed by position, so
same-named providers keep independent health; **#41** (`cache.py`) `get_or_set`
now single-flights concurrent misses on the same key.

**Cosmetic** — **#42** (`report_generator.py`) the executive-summary score is
floored so it never shows a value in a higher band than the printed
classification; **#43** (`storage.py`) EVM addresses are lowercased for identity
so casing no longer fragments a token's history/watchlist/baseline (Solana
base58 preserved verbatim).
